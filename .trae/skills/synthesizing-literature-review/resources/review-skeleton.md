# 综述骨架模板详解

本文档是 `synthesizing-literature-review` Skill 的 resources 参考,详细说明五段式综述骨架的每一部分写什么、怎么组织、引用格式如何规范,并给出方法分类法、对比表模板与趋势分析要点。

> 约定:本文档中的"综述"指 Skill 生成的**综述骨架**(skeleton),而非可直接发表的综述论文。骨架提供结构、聚类、对比表与引用占位符,用户在此基础上填充叙事。所有引用占位符 `[cite:...]` 必须经 `fact-checking-citations` 校验后才能落盘为正式引用。

---

## 一、五段式结构总览

| 段 | 名称 | 核心问题 | 篇幅占比 |
|----|------|---------|---------|
| 1 | 引言 | 这个领域在解决什么问题?为什么做这个综述?选了哪些论文? | ~15% |
| 2 | 分类综述 | 按方法聚类,每类怎么解决问题? | ~35% |
| 3 | 方法对比表 | 横向对比:方法/数据/指标/优势/局限 | ~20%(表格为主) |
| 4 | 研究趋势 | 跨论文的规律:时间/规模/方法族的演变 | ~15% |
| 5 | 空白与展望 | 哪些格子是空的?哪些问题没人做? | ~15% |

五段顺序固定,不得调换。引言定 scope,分类综述纵向铺开,对比表横向收敛,趋势跨段提炼,空白反向回扣——这是一个"定义→展开→对比→提炼→反思"的闭环。

---

## 二、第一段:引言(Introduction)

### 写什么

引言要回答四个问题,每个问题一段,共四小段:

1. **问题定义**:这个领域/主题在解决什么问题?用一两句话把问题陈述清楚,避免泛泛而谈。例如"如何让模型高效处理长序列"比"序列建模"更具体。
2. **scope 与动机**:为什么在这个时间点做这个综述?综述的边界在哪里(包含什么、不包含什么)?
3. **选文标准**:从多少篇里选了多少篇?筛选依据是什么(citation_count?年份?方法代表性)?
4. **综述结构预告**:后续五段分别讲什么,给读者一个地图。

### 怎么组织

- 四小段顺序固定,不得调换。
- 问题定义段**不引用具体论文**——它讲的是领域问题,不是某篇论文的贡献。如果非要引用,用 `[cite:...]` 占位,但通常可以避免。
- scope 与动机段可以引用一两篇开山作或综述,但**必须**经 fact-checking。
- 选文标准段必须给出可复现的筛选条件(如"从 `_high_impact.csv` 中 `area=NL` 且 `citation_count>500` 的 47 篇中,按方法代表性选 8 篇")。

### 引用格式规范

- 引言段的引用稀疏,通常 ≤3 个。
- 每个引用先用 `[cite:DOI]` 或 `[cite:citekey]` 占位,经 fact-checking 后转为 `[[citekey]] (DOI:...)`。
- 不要在引言段堆砌引用——那是分类综述段的职责。

### 示例(骨架片段)

```markdown
## 1. 引言

本综述关注"注意力机制在长序列建模中的应用"。核心问题是:如何让模型在
线性/近线性复杂度下捕获长距离依赖 [cite:"Attention Is All You Need"]。

本综述覆盖 2017–2024 年间 8 篇高被引论文,scope 限定在"自注意力及其
高效变体",不涵盖传统的 RNN/LSTM 注意力(如 [cite:bahdanau2014])。

选文标准:从 `_high_impact.csv` 中 `area=NL` 且 `citation_count>500` 的
47 篇中,按方法代表性(每个方法族至少 1 篇)选 8 篇。

后续结构:§2 按方法聚类综述;§3 方法对比表;§4 研究趋势;§5 空白与展望。
```

## 三、第二段:分类综述(Categorized Synthesis)

### 写什么

按方法分类法(见§七)将入选论文分成若干簇,每簇一个子小节。每个子小节回答:

1. **该簇的共性方法**:这一类方法的共同技术路线是什么?
2. **逐篇叙述**:每篇论文在该路线下做了什么独特的事?与同簇其他论文的差异点在哪?
3. **簇内对比**:同簇论文之间的高层差异(不是逐字段对比——那是§四的事)。

### 怎么组织

- 子小节数量 = 方法簇数量。空簇也要列出(见§七空簇处理)。
- 每个子小节内,逐篇叙述用 bullet list,每篇一个 bullet,以 `[[citekey]]` 开头。
- 簇内对比用一段总结性叙述收尾,不另起表格。
- 叙述基于 literature note 的 annotation 区或 abstract,**不得**凭模型先验编造方法细节。若 annotation/abstract 未覆盖某细节,用 `—(需读全文)` 标注。

### 引用格式规范

- 每篇论文在该段至少被引用一次(在对应簇的 bullet 中)。
- 引用格式:`[[citekey]] (DOI:...)`(首次出现),后续可只用 `[[citekey]]`。
- 簇内对比段的引用用 `[Author, Year]` 行内格式,避免 wikilink 密度过高。

### 示例(骨架片段)

```markdown
## 2. 分类综述

### 2.1 基于全局自注意力

这一类方法保留完整的自注意力矩阵,通过架构优化(如稀疏化、低秩)降低复杂度。

- [[vaswani2017]] (DOI:10.5555/3295222.3295349) — 提出原始 Transformer,
  O(n²) 复杂度,奠定了后续工作的基线。
- [[child2019]] (DOI:10.48550/arXiv.1904.10509) — 稀疏注意力,将复杂度
  降至 O(n√n),但牺牲了全局感受野。

**簇内对比**:两者同为全局注意力路线,但 vaswani2017 以完整注意力换表达力,
child2019 以稀疏化换效率,代表了"表达力 vs. 效率"的根本张力。

### 2.2 基于线性化注意力

...(略)...
```

## 四、第三段:方法对比表(Method Comparison Table)

### 写什么

一张固定的五列对比表,每行一篇论文。这是综述的"信息密度最高"的部分,用户扫一眼即可定位差异。

### 对比表模板

| 方法 | 数据集 | 指标 | 优势 | 局限 |
|------|--------|------|------|------|
| [[citekey1]] (方法简称) | 数据集名(规模) | 指标名=数值 | 一句话优势 | 一句话局限 |
| [[citekey2]] ... | ... | ... | ... | ... |

### 列定义与填写规范

| 列 | 内容 | 填写规范 | 空值处理 |
|----|------|---------|---------|
| 方法 | 方法简称 + `[[citekey]]` wikilink | ≤8 字简称,如"Sparse Transformer" | 不得为空 |
| 数据集 | 主要数据集名(规模) | 括号注规模,如"LongMQA(10k)" | 若 abstract 未提及,填 `—(需读全文)` |
| 指标 | 主要指标=数值 | 用论文自报的最佳数,如"PPL=18.3" | 若无明确数值,填 `—` |
| 优势 | 一句话核心优势 | ≤20 字,聚焦方法层面,不写"性能好" | 不得为空 |
| 局限 | 一句话核心局限 | ≤20 字,来自论文自陈局限或对比可见 | 若论文未自陈且对比不可见,填 `—(需读全文)` |

### 怎么组织

- 行顺序按方法簇分组,簇内按年份升序。簇间用空行或 `**簇名**` 分隔。
- 表格单元格内**不引用**其他论文——对比是横向的,引用已在§三完成。
- 数值必须来自 abstract 或 annotation,**不得**从模型记忆中填写。若 abstract 只给相对提升("+2.3 BLEU")不给绝对值,填"相对提升 +2.3 BLEU"。
- `📜` 前缀标记仅基于摘要的论文(见 SKILL.md 失败策略)。

### 示例(骨架片段)

```markdown
## 3. 方法对比表

| 方法 | 数据集 | 指标 | 优势 | 局限 |
|------|--------|------|------|------|
| **基于全局自注意力** | | | | |
| [[vaswani2017]] Transformer | WMT14 En-De | PPL=4.92 | 奠基性架构,表达力强 | O(n²) 复杂度,长序列不可行 |
| [[child2019]] Sparse Transformer | LongMQA(10k) | PPL=15.7 | 复杂度降至 O(n√n) | 稀疏模式需人工设定 |
| **基于线性化注意力** | | | | |
| [[katharopoulos2020]] Linear Transformer | LRA | Acc=0.52 | O(n) 复杂度 | 表达力显著下降 |
| 📜 [[choromanski2021]] Performer | LRA | Acc=0.48 | 无核近似,理论保证 | 近似误差在长序列累积 |
```

## 五、第四段:研究趋势(Research Trends)

### 写什么

跨论文的规律提炼,回答"这些论文 collectively 告诉我们什么"。趋势不是时间线(那是 `building-citation-timeline` 的职责),而是结构性规律。

### 趋势分析要点(四类必看)

1. **方法族演化趋势**:某方法族是否在扩张/收缩?是否被新族取代?
   - 信号:某族论文数随年份增加;某族指标被另一族超越。
2. **数据规模趋势**:数据集规模是否在增长?是否从合成数据转向真实数据?
   - 信号:数据集列的规模数字随年份递增;数据集名称从"Synthetic-X"变为"Real-X"。
3. **指标关注点迁移**:社区关注的指标是否在变化?从准确率→效率→鲁棒性?
   - 信号:早期论文只报准确率,后期论文加报延迟/吞吐/对抗鲁棒性。
4. **贡献类型迁移**:贡献从"新方法"→"新数据集"→"新分析"?
   - 信号:贡献维度列的类型分布随年份变化。

### 怎么组织

- 每类趋势一个小段,共四小段。
- 每段必须给出支撑该趋势的具体论文引用(经 fact-checking),不得空泛断言。
- 若某类趋势在入选论文中不明显,明确说"本综述范围内未见明显 X 趋势"——不勉强凑趋势。

### 引用格式规范

- 趋势段引用密度中等,每段 2–4 个。
- 用 `[[citekey]]` wikilink,首次出现加 DOI。
- 趋势断言必须可追溯到对比表中的具体行——若对比表不支持该趋势,不得写入。

### 示例(骨架片段)

```markdown
## 4. 研究趋势

**方法族演化**:全局自注意力族(2017–2019)在长序列场景下被线性化族
(2020 起)逐步取代 [[katharopoulos2020]] [[choromanski2021]]。但 2023 年
后混合族重新引入局部-全局混合策略,表明纯线性化的表达力损失不可接受。

**数据规模**:数据集规模从万级 [[vaswani2017]] 增至百万级,但 2023 年
后出现反向趋势——小规模高质量数据集重新受关注。

**指标迁移**:早期只报 PPL/Acc [[vaswani2017]],2021 年起加报延迟与
吞吐 [[choromanski2021]],2023 年起加报对抗鲁棒性。

**贡献类型**:本综述范围内贡献类型未见明显迁移,以"新方法"为主。
```

## 六、第五段:空白与展望(Gaps and Outlook)

### 写什么

从对比表的"空格"反向发现空白。这是综述最有价值的部分——它告诉读者"哪里还没人做"。

### 空白识别的四个来源

1. **对比表的 `—` 单元格**:某论文在某列填了 `—(需读全文)` 或 `—`,意味着该维度未被覆盖。
2. **空簇**:方法分类法中某簇无入选论文(见§七空簇处理)。
3. **指标覆盖空白**:某指标(如鲁棒性)无人报告。
4. **数据集覆盖空白**:某领域/规模的数据集无人用。

### 怎么组织

- 每个空白一个 bullet,格式:`**空白点**:描述 → **潜在方向**:一句话建议`。
- 空白点必须可追溯到对比表的具体行/列或方法分类法的具体簇。
- 展望部分 ≤3 条,每条一句话,聚焦"如果有人做这个会怎样",不展开技术细节。
- **不得**在此段引入新引用——所有引用应在前四段已出现。若需引入新论文,回到§二/§三补充。

### 示例(骨架片段)

```markdown
## 5. 空白与展望

- **空白点**:线性化注意力族(§3)无一报告对抗鲁棒性指标 →
  **潜在方向**:在 LRA 上加对抗扰动评估线性注意力的鲁棒性。
- **空白点**:方法分类法中"基于规则"簇无入选论文 →
  **潜在方向**:补充规则-神经混合方法的工作(如 retrieval-augmented)。
- **空白点**:数据集列显示 2023 年后无新大规模数据集 →
  **潜在方向**:构建更长(>1M tokens)的真实长序列基准。

**展望**:
1. 混合族(全局+线性)可能成为 2025 年后的主流路线。
2. 鲁棒性指标若被社区采纳,将重新洗牌方法族排名。
3. 硬件感知的注意力设计(针对推理延迟)是未被覆盖的工程方向。
```

## 七、方法分类法(Method Taxonomy)

### 默认四类(按技术路线)

本 Skill 默认采用以下四类方法分类法,适用于大多数 AI/ML 主题:

| 类 | 名称 | 判定特征 | 典型代表 |
|----|------|---------|---------|
| A | 基于规则(Rule-based) | 方法核心是人工规则/模板/启发式,无学习参数 | 正则、模板匹配、专家系统 |
| B | 统计学习(Statistical Learning) | 方法核心是统计模型(含传统 ML),参数从数据学习 | HMM、CRF、SVM、GMM |
| C | 深度学习(Deep Learning) | 方法核心是神经网络(含注意力),端到端学习 | CNN、RNN、Transformer |
| D | 混合(Hybrid) | 显式组合≥2 种技术路线(如规则+神经、统计+神经) | retrieval-augmented、神经符号系统 |

### 分类判定规则

1. **看方法核心,不看辅助组件**:若一篇论文用神经网络做主架构但加了一个规则后处理,主分类是 C(深度学习);只有当混合是"核心机制"时才归 D。
2. **允许复标签**:一篇论文可同时归 C 和 D(如"深度学习 + 混合"),只要两条路线都是核心。
3. **不勉强归类**:若论文方法不符合任何一类,新增"其他"簇,不要硬塞。新增簇需在分类综述段说明判定特征。
4. **领域适配**:对于非 AI 主题(如数据库、系统),Skill 应根据入选论文的方法分布重新定义分类法(如"基于索引/基于学习/基于混合"),并在综述引言段声明所用分类法。

### 扩展分类法

若默认四类不适用,Skill 在 Step 2 聚类时根据 abstract 中的方法关键词重新归纳,但必须:

- 在引言段声明"本综述采用自定义分类法:X / Y / Z"。
- 在分类综述段每簇开头给出判定特征。
- 自定义分类法仍遵循"按技术路线分"的原则,不得按"按年份"或"按数据集"分(那是趋势段的事)。

### 空簇处理

若某类在入选论文中无代表:

- 分类综述段仍列出该类小节,内容为"本类暂无入选论文"。
- 空白与展望段将其识别为空白点(见§六)。
- 不从外部补论文凑数——综述的 scope 由用户输入决定。

## 八、引用格式规范(Citation Format)

### 占位符格式(Step 3 生成,Step 4 校验前)

| 场景 | 占位符格式 | 示例 |
|------|-----------|------|
| DOI 已知 | `[cite:DOI]` | `[cite:10.5555/3295222.3295349]` |
| 仅 citekey 已知 | `[cite:citekey]` | `[cite:vaswani2017]` |
| 仅标题片段已知 | `[cite:"标题片段"]` | `[cite:"Attention Is All You Need"]` |

占位符**不得**出现在最终写入 vault 的文件中——它们是 fact-checking 前的中间态。

### 最终格式(Step 4 校验通过后)

| 场景 | 最终格式 | 示例 |
|------|---------|------|
| 首次出现 | `[[citekey]] (DOI:...)` | `[[vaswani2017]] (DOI:10.5555/3295222.3295349)` |
| 后续出现 | `[[citekey]]` | `[[vaswani2017]]` |
| 行内引用 | `[Author et al., Year]` | `[Vaswani et al., 2017]` |
| 文献无 literature note | `[[citekey]]?` | `[[child2019]]?` |

`?` 后缀标记 dangling link,提示用户运行 ZotLit import 生成对应 literature note。

### 校验未通过的处理

| 校验结果 | 最终格式 | 附加处理 |
|---------|---------|---------|
| VERIFIED + SUPPORTED | `[[citekey]] (DOI:...)` | 无 |
| VERIFIED + UNSUPPORTED | `[[citekey]] (DOI:...)` ⚠️ | 行内加 `⚠️ 论断未被摘要支持` |
| MISMATCH | `[[citekey]] (DOI:...)` ⚠️ | 行内加 `⚠️ 元数据不符: {差异}` |
| INCONCLUSIVE | `[[citekey]] (DOI:...)` ⚠️ | 列入文末"需人工核对"清单 |
| NOT_FOUND | (删除) | 删除引用与依赖句,或向用户索要 DOI |

### 文末引用清单

综述文件末尾附一个 `## 引用清单` 章节,列出所有引用及其校验状态:

```markdown
## 引用清单

| citekey | DOI | 校验状态 | 论断核对 |
|---------|-----|---------|---------|
| vaswani2017 | 10.5555/3295222.3295349 | ✅ VERIFIED | ✅ SUPPORTED |
| child2019 | 10.48550/arXiv.1904.10509 | ✅ VERIFIED | ⚠️ UNSUPPORTED |
| ... | ... | ... | ... |
```

该清单由 `fact-checking-citations` 的报告直接填充,不由本 Skill 重新生成。

## 九、整体骨架模板(可粘贴)

以下是完整的五段式骨架模板,Skill 在 Step 3 生成、Step 4 校验后填充:

```markdown
---
type: review
topic: {topic-slug}
paper_count: {N}
citekeys: [{citekey1}, {citekey2}, ...]
generated: {YYYY-MM-DD}
fact_check_status: {passed|partial|failed}
unverified_citations: [{placeholder1}, ...]
---

# {主题} 综述

> 生成时间: {YYYY-MM-DD HH:MM}
> 论文数: {N} | 有 literature note: {a} | 仅摘要: {b} | 仅元数据: {c}
> 引用反查: {passed}/{total} 通过

## 1. 引言

{问题定义}

{scope 与动机}

{选文标准}

{结构预告}

- [[{citekey2}]] (DOI:...) — {该篇独特贡献}

{簇内对比}

### 2.2 {方法簇 B 名称}

## 3. 方法对比表

| 方法 | 数据集 | 指标 | 优势 | 局限 |
```

## 十、质量自检清单

- [ ] 每篇入选论文至少在分类综述段被引用一次。
